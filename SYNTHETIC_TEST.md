# Синтетический тест повторов

Запуск из корня проекта:

```bash
./scripts/run_synthetic_test.sh
```

Скрипт последовательно выполнит один тест для каждого `x = 0; 0.5; 1; 1.5; 2`
и каждого из трёх методов: k-меры, замороженный NT, обученный NT с выбранной проекцией.
Нового обучения нет. Требуются сохранённые `data/model/` и
`runs/baseline/best.pt`. При первом запуске `uv` синхронизирует окружение по lock-файлу.
NT по умолчанию работает на CUDA; CPU можно явно выбрать через `--device cpu`.

Параметры по умолчанию:

| Параметр | Значение |
|---|---:|
| Итоговая длина случайного генома | 500 000 bp |
| Число вставленных копий одного нового семейства | 150 |
| Длина исходного повтора и каждой копии | 300 bp |
| Уровни x | 0; 0.5; 1; 1.5; 2 |
| Число замен на каждую копию | 0; 75; 150; 225; 300 |
| Длина окна / шаг | 800 / 200 bp |
| Окон на один геном | 2497 |
| Минимальный промежуток между копиями | 800 bp |
| Seed | 42 |
| Размер NT-батча | 8 |
| CPU-потоки | 1 |

Фон и исходный повтор — независимо сгенерированные строки с равновероятными A/C/G/T.
Участки фона заменяются копиями одинаковой длины: **500 000 — итоговая длина**,
а не длина до вставки. Позиции случайны и не пересекаются. Промежуток 800 bp выбран,
чтобы в одно окно не попадали две вставки; его можно изменить через `--min-gap`.
Ориентации копий случайны и зафиксированы между уровнями x.

На копию выполняется **ровно `round((x / 2) * L)` замен**. Позиции выбираются с
возвращением; каждая операция заменяет текущую букву одной из трёх других.
Для каждой копии свой независимый поток случайных операций. При увеличении x
используется более длинный префикс этого же потока. Фон, исходный повтор и позиции
вставок остаются одинаковыми. Итоговую долю различающихся букв не пытаемся подгонять.
План мутаций и фактически вставленные копии сохраняются.

Каждое окно получает представление. Далее для всех методов используется одинаковый
путь: FAISS top-30 → связи по cosine threshold → Leiden, resolution 1.
Связи между перекрывающимися окнами запрещены. Окна сообщества, перекрывающиеся или
соприкасающиеся по координатам, объединяются в локусы. Сообщество с единственным
локусом отбрасывается. Алгоритму не передаются исходный повтор, координаты вставок,
истинное число семейств или число копий. Семейство синтетическое и не использовалось
при дообучении.

Для воспроизводимого выбора порога есть отдельные **512 случайных фоновых окон**,
одинаковые для всех методов. Порог каждого метода — квантиль 0.9999 сходства
разных фоновых окон. Он вычисляется до обработки тестовых копий и не меняется
между x. Это калибровка по фону, а не подбор по ответам теста. Это также не гарантия
заданного false positive rate на полном геноме: граф и объединение окон меняют
единицу обнаружения. Все пороги записываются в `thresholds.json`.

В текущем основном checkpoint выбран projection stage: Transformer заморожен,
обучена проекция. Для отдельного сравнения модели с обученными последними блоками
можно явно указать `--checkpoint runs/baseline/finetune_best.pt` или контекстную
модель `--checkpoint runs/context/best.pt`. Выбранная стадия checkpoint выводится в лог
и сохраняется в manifest. Векторы NT усредняются по двум ориентациям; k-меры также
канонизированы по обратному комплементу.

## Логи и файлы

По умолчанию создаётся новая папка `runs/synthetic_<дата-время>_UTC`. Можно задать её:

```bash
./scripts/run_synthetic_test.sh --output runs/my_synthetic_test
```

Непустая папка не перезаписывается. После прерывания частичные результаты остаются;
для нового запуска нужна новая папка. Возобновление с места прерывания не реализовано.

В терминале и `progress.log` будут видны подготовка входов, загрузка модели,
калибровка порога, обработка окон, FAISS/Leiden и метрики. Во время извлечения векторов
каждые 25 батчей выводятся процент, скорость, прошедшее время и ETA текущего этапа.
Частоту можно изменить через `--log-every 10`.

Из другого терминала:

```bash
tail -f runs/my_synthetic_test/progress.log
cat runs/my_synthetic_test/status.json
```

Основные файлы:

- `summary.tsv`, `summary.json` — 15 строк: 3 метода × 5 уровней x. Обновляются после
  каждой завершённой комбинации; это главная таблица сравнения.
- `status.json` — running / complete / failed / interrupted; ошибки также попадают
  в лог с traceback, процесс возвращает ненулевой exit code.
- `manifest.json` — параметры, модель, checkpoint, контрольные суммы кода и определения
  метрик; `thresholds.json` — пороги всех методов.
- `background.fa`, `ancestor.fa`, `placements.jsonl`, `mutation_plan.npz` — общий дизайн.
- `calibration_background.fa`, `calibration.*.npz` — отдельные фоновые окна и их векторы.
- `x_0/`, `x_0p5/`, `x_1/`, `x_1p5/`, `x_2/` — геномы, копии и истинные координаты.
- Внутри каждого `x_*/<метод>/`: `metrics.json`, `embeddings.npz`, `windows.tsv`,
  `edges.tsv`, `loci.tsv` с координатами и `family_id`, `copy_assignments.tsv`
  с сопоставлением вставок и найденных локусов.

## Как читать метрики

`locus_precision`, `locus_recall`, `locus_f1` оценивают обнаружение координат.
Истинные и предсказанные локусы сопоставляются **один к одному** при IoU >=0.2:
сначала максимизируется число сопоставлений, затем их суммарный IoU. Порог 0.2
зафиксирован для разрешения окон 800 bp при длине копии 300 bp. Он не подбирается
для каждого x. Дублирующие предсказания считаются FP, пропущенные копии — FN.
Один огромный предсказанный участок не получает зачёт за все вставки.

`best_family_recall` — какая доля из 150 копий попала в крупнейшую по числу
правильных находок группу. `best_family_precision` — доля правильных локусов в ней.
Лучшая группа выбирается **только при оценке**, а не для управления кластеризацией.
`detected_family_parts` показывает дробление найденных копий по группам.

`pair_f1` одновременно учитывает группировку, пропущенные копии и ложные находки:
в оценку входят все истинные копии и все несопоставленные предсказанные локусы.
Каждый ложный локус получает отдельную истинную фоновую метку; пропущенные копии
считаются шумом, каждая отдельно. Поэтому группа, слившая копии с фоном, теряет
precision. При одном вставленном семействе нельзя оценить разделение нескольких
настоящих семейств — для этого нужен другой эксперимент.

`base_precision`, `base_recall`, `base_f1` сравнивают объединения покрытых оснований.
Они дополняют оценку локусов: очень широкие найденные интервалы дают низкую точность
по основаниям даже при хорошем покрытии вставок. Из-за фоновых краёв окон точность
по основаниям может быть заметно ниже точности нахождения локусов.

## Другие параметры и быстрая проверка

```bash
./scripts/run_synthetic_test.sh --batch-size 16 --output runs/synthetic_batch16
./scripts/run_synthetic_test.sh --checkpoint runs/context/best.pt \
  --output runs/synthetic_context
./scripts/run_synthetic_test.sh --help
```

Короткий технический запуск всех трёх методов на 6 кб и трёх копиях:

```bash
./scripts/run_synthetic_test.sh \
  --genome-size 6000 --copies 3 --repeat-length 120 \
  --window-size 240 --stride 120 --calibration-windows 24 \
  --batch-size 2 --x-values 0 1 --log-every 10 \
  --output runs/synthetic_smoke
```

Такой короткий запуск проверяет работоспособность, а не качество метода:
24 окна недостаточны для устойчивой оценки хвостового квантиля.
Полный тест на 500 кб оставлен для самостоятельного запуска пользователем.
